# Catch up w/ Alec

## Attendees

Kris Brown (note creator) from Humans Not Robots <kris@humansnotrobots.com>

## Agentic Build Architecture (Coolbox + Capability Levels)

- Coolbox: Docker wrapper around Claude Code handling permissions, caging, and environment mounting
- Runs automated agents in a contained environment, no permission prompts, no container escape
- Mounts transcripts and relevant context to feel native, without exposing anything else
- Capability levels (L1 to L4) define how much autonomy the agent has:
- L1: human instigates each step (spec, review, build)
- L2: pre-approved tickets run automated in a small batch
- L3: CI-triggered, always watching for new work (currently being wired up)
- L4: lights-out factory, given a PRD and builds the product end-to-end with full PR/linear visibility
- Spec pipeline: ticket raised via Linear template, spec written and reviewed by models, ADRs generated and committed to repo at build time
- Holdout agent: spun up in an isolated environment with only withheld tests, runs against a live build to validate without access to code or specs
- Review modes: standard, adversarial, common values, and quorum (multiple model families synthesized)
- Model selection by stage: reasoning-heavy models for spec and eval; lightweight/local models for build (no decisions required)
- Mosh shell used for SSH over spotty connections, keeping agent sessions alive across drops

## Skills, Governance, and the Human Capability Model

- Skills are slash commands that modify agent behavior: some are structural, some are opinionated (agile-style, splitting PRDs into tickets)
- Skills assigned per agent role: e.g. a spec agent gets different skills than a build agent
- Governance skills add guardrails, especially relevant for lower-capability users (the “vibe coder” profile)
- Human capability model (the simulator experiment):
- Frames task outcomes as a function of intelligence, learning ability, skills/knowledge, and governance
- AI amplifies trajectory in both directions: better outcomes for prepared users, worse for unprepared ones
- Profiles modeled: vibe coder (no governance, no learning), average trained professional, forward-thinking architect with guardrails
- Key insight: matching intelligence level to task complexity sets the midline; governance deflects the trajectory upward

## Knowledge Islands and Tooling

- Two repo types: engineering-style depot and knowledge-based repo
- Knowledge island structure: admin, calendar, pillars, resources, and streams (work stream tracking)
- Recap loop: on completing work, agent reviews completed items, flags outstanding tasks, captures lessons, and generates named actions pushed to roadmap
- Handoff mechanism: outbound and inbound queues between repos, knowledge-as-file rather than work-as-message
- Custom MCPs built to keep tool surface small; MCP Porter used so tools are discovered on demand rather than loaded into context
- Linear MCP dropped due to context cost; managing Linear via other means
- Live artifacts in Claude UI used as a command center: repo status dashboard, quick edits, observability at a glance
- Legal case management built on the same knowledge island pattern: triple fact-checks, judicial intervention simulation, opposing counsel simulation

## R\&D Direction and Collaboration

- Plan: Kris and the other person do R\&D together, two days a week to start, with a view to increasing as bridging is in place
- Engineering team handles execution; Kris focuses on governance, architecture, and new capability building
- Goal: build things to sell (AI tooling/products), not just internal automation
- Value measurement discussion: current gap is attribution of cost to value
- Measurement exists, concept exists, but no model yet for “what is value” or tracing AI contribution to business outcomes
- Sponsorship/experience-point model floated: companies set their own value targets, AI work earns points against those targets
- Linking into ALM (e.g. Linear) to tie completed work back to cost and value distribution seen as a promising direction
- Gastown mentioned as a comparable: crowdsourced, RPG-style AI orchestration with tokenization layer; noted as very similar in concept to what’s being explored
