# Agent Host

## Outcome

Move agent work into the Techne footprint on an agent host, inside the standing exemption from the [[Techne Programme Hold]]. Agent hosts are harness-defined recipes that a person binds into named instances, and the prototype is reviewed before the exemption is kept, widened or withdrawn.

This Project sits in [[Initiatives/techne|Techne]]. It and [[baseline-rollout]] do not gate each other.

[[Hosts, Roles and Layers]] explains how a host is built in layers and which role `vega` plays.

---

## Notes

- **Exemption.** The [[Techne Programme Hold]] carries one standing exemption: setting up and operating the single agent host `ki-techne-agent-host`, built and torn down under the binding owner's administrator session and operated through the account-local operator role, with no automatic lapse and no fixed review date ([[GDR-KI-ARCADIA-004-standing-agent-host-exemption-from-the-techne-programme-hold|GDR-KI-ARCADIA-004]]). The prototype review decided keep, with `agent-host` staying a recipe; the exemption is revisited when the hold is reshaped. Paperclip, Kitteth, Telegram, wider K3s, the controller and every other environment stay held.
- **Model.** `agent-host` is the first recipe, and its first binding, rendered by chezmoi into `~/.config/techne/`, shares the name. [[ADR-KI-ARCADIA-006-techne-implementation-ownership|ADR-KI-ARCADIA-006]] records the ownership split.
- **Durability.** [[ODR-KI-ARCADIA-001-keeping-work-safe-on-the-agent-host|ODR-KI-ARCADIA-001]] decides how work on the host stays safe: a structured status verdict, stop that warns, guarded rebuild and withdraw, declared pins, an expiry view, the operator's workstation as the roadmap writing checkout, and the two-checkout rule.
- **Identity and egress.** The host's GitHub token and Claude login are the binding owner's own until unattended agents arrive. The security group allows TCP 443 and 80 to any address; named-destination egress is still open.
- **Durability rollout.** Every [[ODR-KI-ARCADIA-001-keeping-work-safe-on-the-agent-host|ODR-KI-ARCADIA-001]] record is captured in its owning repository: the guarded-work pilot and the pins-and-expiries record in `ki-techne-harness`, guarded host commands in `tools-techne`, the recipe's own two-checkout and writing-checkout instructions for Claude and Codex in the pins-and-expiries record, Kris's personal wording of the rule in the chezmoi source, the `ki` refusal of roadmap writes on the host marker in `tools-ki`, and a non-blocking handoff on where a writing-checkout designation lives in `ki-agentic-harness`. The pins-and-expiries record also removes the review date from host status. The guarded-work pilot and the pins-and-expiries record are delivered, accepted and live: the 2026-10-08 setup run found every repository safe, no pin drift and a silent banner. A 2026-10-09 setup rerun took up the raised `ki` pin with no drift.
- **General design.** Kris set the direction on 2026-10-08: the recipe should feel like working locally on another machine, a cloud instance today or an owned machine later, and it is a general project rather than Kris's own set-up. A generic review followed, and Kris approved its recommended changes the same day, with zsh rather than bash as the default shell. [[ODR-KI-ARCADIA-001-keeping-work-safe-on-the-agent-host|ODR-KI-ARCADIA-001]] and [[ADR-KI-ARCADIA-003-the-agent-host-workstation-model|ADR-KI-ARCADIA-003]] were amended so they hold for any binding owner and any target, cloud or owned, Linux or macOS, naming Kris's tools only as examples. The harness's not-started records now follow it, and a new triage record there removes the person-specific recipe defaults (the repository list, the instruction file list and the `chezmoi cat` path). A neutral `host.id` and guide fixes went into the guarded-work pilot. Still undecided: splitting the operator guide, an owned-host provider and moving the neutral scripts out of the AWS folder.
- **Hold prerequisites.** Lifting the hold needs a local review-to-live-main cycle with recovery ([[paperclip-bootstrap-and-recovery]]), an account of what Paperclip supplies versus what Techne must add (harness working analysis `+/paperclip-as-techne-prior-art.md`), and a repository-owned remote-delivery policy.
- **Workstation.** [[ADR-KI-ARCADIA-003-the-agent-host-workstation-model|ADR-KI-ARCADIA-003]] decides how the host becomes the binding owner's working machine: the `agent-host` recipe's Rig profile for shared tools with a variant per target OS, the owner's profile payload for the personal layer (for Kris, Cheztoi from the chezmoi source), Rig staged in three steps, the shell a per-binding choice with zsh as the default, no detached delegation on the host yet, no personal-configuration tool on the host, and Rig the only new binary. Its rollout is captured in `ki-techne-harness` and the chezmoi source, and each record names this Project. The Rig profile is folded into the harness's pins-and-expiries record. The pilot is one harness workstation record paired with the chezmoi Cheztoi host-profile record, after the durability pilot and the Rig profile stage; its payload hook becomes the only route for personal instructions. The `ki` Rig provider, the binding's shell set at the next rebuild, the gated move of the shared tools to `rig apply` and the host's detached delegation follow. The pilot pair is planned and awaits Kris's approval; planning found that `techne host setup` already passes the profile setting through, so `tools-techne` needs no change for it.
- **Bundle walkthrough.** [[workstation-bundle-walkthrough]] in this Project's `design/` folder explains what the workstation bundle sends to the host and recommends keeping the per-host sharing manifest chezmoi-native (`chezmoi archive` driven by a manifest file) rather than in a skill or a Rig extension; it awaits Kris's reading before the pilot's chezmoi half is approved.
- **Host set-up follow-ups.** An MCP source for the host (the `BIND-2` audit failures), and moving the three `ki` behaviour fixes found live (`ki dev local set` while the checkout is active, bootstrap without `--refresh`, the estate `diag` exit status) to `tools-ki`.
- **Controller as a recipe.** The held controller (`techne controller`, stack `ki-techne-ops-007-primary`) is a delegation-capable recipe and could later become a `techne host` binding, retiring `techne controller`. Revisit when the hold lifts.
- **CLI consistency.** `mgit` with no or an unknown subcommand runs its default action across every repository; fold into the `tools-mgit` help fix if Kris agrees.
- **Laptop relief.** Capture a standing-load record in its owning repository, then pause non-essential Rig agents and trim the MCP inventory; the chezmoi mcporter stall is related.
- **Techne cloud readiness.** An Arcadia record for the held full footprint - the Paperclip comparison promoted, the reconstructability inventory and the Paperclip workload design - only if Kris moves to reshape the hold.
- **Design outcomes.** The durability and workstation design loops are consolidated in [[ODR-KI-ARCADIA-001-keeping-work-safe-on-the-agent-host|ODR-KI-ARCADIA-001]] and [[ADR-KI-ARCADIA-003-the-agent-host-workstation-model|ADR-KI-ARCADIA-003]]; their working papers are deleted.
