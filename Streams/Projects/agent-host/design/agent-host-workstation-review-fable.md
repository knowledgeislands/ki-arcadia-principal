# Agent host as Kris's working machine: review by fable

**Reviewer:** Claude Fable 5.1 (claude-fable-5-1) in Claude Code · **Date:** 2026-10-07 · **Read-only:** yes

## Own view

The brief's model is sound: split the subject into tools and personal configuration, keep the recipe person-neutral, and deliver Kris's layer as an allowlisted artefact rendered on the Mac and pushed through the one reconcile path the host already has. That is the natural extension of what `setup.sh` already does for the Claude instruction files, it respects ADR-TECHNE-003's ownership split, and it keeps chezmoi, 1Password and the personal-account `krisb/dotfiles` remote off the host. I would not run `chezmoi apply` on the host against the Mac source, for the reasons the brief gives and one more: ADR-DOTFILES-008 models the workstation once in Rig, and the Rig catalogue declares `ki`, `mgit` and chezmoi as macOS-only Homebrew formulae, so the Mac source has no notion of a second platform to apply to.

Two things changed under the brief this evening and the addendum did not catch them. First, `DOTFILES-UE-020` is no longer a held record waiting to be released: the chezmoi source cancelled it as rejected at 21:38 and pruned it at 21:44, citing decision 17 of the state-of-play design. Point 14 and the Project note's "first slice of the Cheztoi profile work" are therefore overtaken; the rollout must capture a new chezmoi record, and Kris should say whether the rejection was of the stale record or of the Cheztoi idea. Second, the agent-host durability decisions were committed at 21:44 and they already settle the baseline half of point 9 (declared pins in one harness file, drift reported against pins and the Mac) and add a bound the brief does not mention: the Mac checkout is the roadmap writing checkout for every Knowledge Islands repository, enforced by a host marker in `ki`. "Usable like Kris's machine" has to be read inside that bound.

On the shell, the brief's conclusion that a zsh login waits on another stack rebuild is stronger than the evidence. The stack's `useradd` sets Bash and `techne` cannot `chsh`, but `converge.sh` already owns `.profile` and `.bashrc` and can hand an interactive session to zsh without root. Given that a rebuild now costs a fresh Tailscale key and device removal, the pilot should use the user-level route and fold `--shell /bin/zsh` into the next rebuild that happens for another reason.

The pilot set the brief proposes is right and smaller than it looks. `claude-bg` is already a chezmoi-managed Bash script with its own test and a Linux-safe detach path, so delivering it is one allowlist entry. `mgit` installs by its release installer. The one genuine design decision left is where the host's personal tool list is declared, Rig or the profile, and the merged report should put that to Kris rather than let it fall out of the pilot.
