# Agent host as Kris's working machine: brief

**Owner:** Kris Brown · **Owning repository:** knowledgeislands/ki-arcadia-principal (Project `agent-host`, Initiative `techne`) · **Date:** 2026-10-07

## Problem

The agent host `ki-techne-agent-host` is built for agents Kris starts in a session: it has the KI toolchain, Claude Code, Codex and the estate's repositories, and nothing of Kris's own. Kris wants to use it much like the Mac - the same command-line tools (`mgit`, `ki`, `techne`, chezmoi and Cheztoi) and enough personal configuration that a session there feels like home. Nobody yet owns delivering those tools and that configuration, deciding which subset is safe to put on the host, or keeping them current. The one record that touches this, `DOTFILES-UE-020`, is held on two records that no longer exist.

## Owner's proposal

> "I need to be able to use the agent host much like I'd use my own machine. So, I need some of the tools on there that I use command line tools, so things like mgit, ki, techni itself, even, and then obviously, I think I had Chezmoi and Cheztoi. So that point becomes more relevant…"

## Reflection

1. The subject is two concerns with different owners: **tools** (executables on `PATH` at known versions) and **personal configuration** (shell, aliases, helpers such as `claude-bg`, editor and Git preferences, Claude instructions). The design should name an owner for each rather than one mechanism for both.
2. Under `ADR-TECHNE-003`, what every agent session needs belongs to the recipe (`ki-techne-harness`), and what reflects Kris's own choices belongs to Kris's personal layer, rendered by chezmoi. `mgit`, chezmoi and shell taste are personal; `ki`, mise, Bun, Node, Codex and Claude Code are recipe baseline. `techne` is arguable.
3. "Cheztoi" should be read as the render-on-Mac projection `UE-020` already describes: chezmoi stays on the Mac, renders an explicit allowlist of host-safe files and tool pins into an artefact, and the host receives the artefact. This matches `UE-020`'s Boundary (no chezmoi runtime dependency, no secrets), the existing `setup.sh` pattern (`chezmoi cat` into a pushed payload), and the credential constraint (the host cannot reach `krisb/dotfiles`, and must not hold 1Password access).
4. Running chezmoi itself on the host against the full source is the wrong default: the source has no platform gating, resolves 1Password at apply time, carries mcporter, Paperclip and launchd material the exemption keeps off the host, and would collide with `converge.sh` over mise and `~/.claude`. If Kris wants chezmoi on the host as a tool, it should be for a separate host-only source or for inspection, not `chezmoi apply` of the Mac source.
5. The profile is an allowlist, never a denylist: each file or tool enters by name, so a new Mac-side secret or Mac-only helper cannot leak by default.
6. Delivery should reuse the one reconcile path the host already has - `techne host setup` running the recipe's `setup.sh`, which stages a payload and runs `converge.sh`. The recipe gains a generic, person-neutral hook ("apply the person's profile payload if one is supplied"); the person's binding or chezmoi supplies the payload. No second sync channel, and no scheduled sync, because the exemption allows no unattended agents and a pull-on-demand model keeps Kris in control.
7. `mgit` is a clean fit: Bash and Git, a Linux installer, and the host already reproduces the Mac's `~/workspaces/kit` layout it walks.
8. `techne` on the host is of limited use as an operator tool: it acts on hosts from outside with AWS profiles, Tailscale and SSH, none of which the host holds or may hold, and its bindings live on the Mac. Its practical uses there are `recipe list`, `diag` and developing `tools-techne`, which the repository checkout already supports through `bun run`. Installing it is cheap, but it must not gain AWS credentials or a binding pointing at the host itself.
9. "Staying current" needs one source of truth per pin. Today `converge.sh` hard-codes pins it claims match the Mac and they do not (`ki` 0.7.1 against 0.8.1; Node 24 against 24.21.0). Baseline pins should stay in the recipe and be bumped by release; personal tool pins should come from the profile; and `techne host status` should report drift between host and declared versions rather than silently diverging.
10. `zsh` is not yet Kris's shell on the host: the rebuild installs the package but `useradd` still sets `/bin/bash`, `techne` cannot `chsh` without `sudo`, and `env.sh` is sourced only from `.profile`, `.bashrc` and Husky. A zsh login needs a stack change (`--shell /bin/zsh`) and `converge.sh` sourcing `env.sh` from `.zshenv` or `.zprofile`, before a personal zsh profile is useful.
11. The host-safe zsh profile is a subset of the Mac's: Homebrew, oh-my-zsh, Granted, headroom and Codex multi-auth fragments are Mac- or credential-bound. The first slice should ship only portable fragments (XDG, path, history, prompt, aliases, completions for the delivered tools), which means the chezmoi source needs a host target or a projection filter it lacks today.
12. The rendered Claude instructions already reference tools the host lacks (`~/bin/claude-bg`), so the instructions and the tools they name must travel together: either the profile delivers `claude-bg`, or the host gets a host variant of `delegation.md`.
13. Everything here is within the exemption's scope as "rerunnable workspace setup, updates and status" of the one host, provided it adds no credential, no unattended process and no reach beyond the host. Nothing needs the hold reshaped.
14. `DOTFILES-UE-020`'s hold is stale on both counts and should be released and rescoped: from a generic portable profile awaiting a remote-substrate contract to the agent host's personal profile under the recipe and binding model, with its current Goal and Boundary otherwise kept.
15. Rollout: a pilot that proves the path end to end with the smallest useful set - `mgit`, `claude-bg`, the zsh login and a minimal shell profile - before chezmoi-rendered configuration grows. Records span `ki-techne-harness` (stack shell, `converge.sh` profile hook, pins and drift report), chezmoi (`UE-020` rescoped: allowlist, projection, host binding values), and possibly `tools-techne` (passing the profile through `host setup`, drift in `host status`). Arcadia holds the design and the Project link.
