# Keeping work safe on the agent host: review by Fable 5.1

**Reviewer:** Claude Fable 5.1 (claude-fable-5-1) · **Date:** 2026-10-07 · **Read-only:** yes

## Own view

The principle is right: on the host, only a pushed branch counts, and the disk is disposable by rule. The brief's own evidence, though, shows the guard it proposes can only be read while the host is running and on the tailnet. After the kill switch's second step, or on a stopped host, status is unreadable, so a withdrawal teardown would go through the override every time. The guard must be designed for "unreadable" as the normal withdrawal case, not the exception.

The highest-value, smallest change is splitting rebuild from withdrawal as two named operations. It alone would have avoided today's hand workaround. `techne host teardown` is a half-measure today: it terminates under the operator role, which the runbook says may only start and stop, and it leaves the stack that blocks the next build. It should become a pass-through to the harness destroy path under the admin profile, or be withdrawn until it is.

Pins should be declared in the harness and bumped by commits, not mirrored from whatever the Mac runs that day. The Mac is the roadmap writer now, enforced by a mechanical marker on the host rather than prose. The pilot should be one harness record, landed before the pending rebuild so Kris's rebuild is its live test.
